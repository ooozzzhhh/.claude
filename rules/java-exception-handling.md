# Java 异常处理与报错规范

供应链计划系统（DFP/SOP/MPS/MRP/MDS/AMS 等）所有 Java 模块**必须遵循**本规范，覆盖前端交互、业务逻辑、数据访问全层级。使用平台统一异常类 `BusinessException`。

## 1. 抛出层级

业务异常**仅在 Service 层抛出**，Controller/DAO 不得直接抛 BusinessException 或 BaseResponse.error。DAO 异常必须在 Service 层捕获并转换。

```java
// ❌ BAD - Controller 层
@PostMapping
public BaseResponse<?> save(@RequestBody DTO dto) {
    if (dto.getName() == null) {
        return BaseResponse.error("名称不能为空");
    }
    return service.save(dto);
}

// ✅ GOOD - Service 层
public void save(DTO dto) {
    if (dto.getName() == null) {
        throw new BusinessException(BusinessErrorEnum.XXX_PARAM_MISSING_01.getI18nErrordesc());
    }
    // ...
}
```

## 2. 异常类型与枚举

禁止 `RuntimeException`/`Exception`。必须使用 `BusinessErrorEnum` + 国际化。**必须使用 `getI18nErrordesc()` 获取国际化文案**，禁止使用 `getDesc()`。禁止在循环/高频调用中频繁抛出异常（异常仅用于异常场景，不用于业务逻辑判断）。

**业务大类编码**：DFP（需求计划）、SOP（产销协同）、MPS（主生产计划）、MRP（物料需求计划）、MDS（主需求计划）、SCH（生产排程）、SYS（系统通用）。编码格式：`业务大类前缀+3位序号`，如 DFP001、SOP001、MPS001、MRP001、MDS001、SCH001、SYS001。**注意编码唯一性，新增编码时要和已有的编码区分。**

**错误码与文案维护位置**：

| 维护项 | 维护位置 |
|--------|----------|
| 错误码定义 | `BusinessErrorEnum` 枚举，`code` 字段（关联国际化配置 key） |
| 错误码与文案映射 | `messages_zh_CN.properties`（中文）、`messages_en_US.properties`（英文），key = 错误码，value = 文案模板（支持 `{0}`、`{1}` 占位符）。**value 中应包含错误码**，如 `MDS001=[MDS001] 物料不存在，请确认后重试。`，确保返回前端的报错语句含错误码。 |
| 加载方式 | 通过 `I18nUtil.getString(code)` 加载，`MessageFormat.format` 填充占位符 |

**新增错误码流程**：
1. **先查找是否可复用**：查询 `BusinessErrorEnum` 枚举和 properties 文件，检查该模块（如 MDS）是否已有适用的错误码（场景相同或相近）
2. **若无可复用，则新增**：找到该模块已有错误码的最大序号，新错误码序号为最大序号 + 1（如已有 MDS001～MDS005，则新增 MDS006）
3. **同步维护**：同时在枚举中定义、并在 properties 文件中补充对应 key-value

优先复用可避免错误码膨胀，新增时确保编码唯一性。

```java
// ❌ BAD
throw new BusinessException("用户不存在!");
throw new BusinessException(e.getMessage());
throw new RuntimeException("操作失败", e);

// ✅ GOOD
throw new BusinessException(BusinessErrorEnum.MDS_MATERIAL_NOT_EXIST.getI18nErrordesc(materialCode));
```

## 3. 禁止技术信息透传

`e.getMessage()`、`e.toString()`、堆栈、SQL 仅写日志，**禁止**返回前端。

```java
// ❌ BAD
catch (Exception e) {
    return BaseResponse.error("操作失败:" + e.getMessage());
}
throw new BusinessException(e.toString());

// ✅ GOOD
catch (Exception e) {
    log.error("操作失败, errorCode={}", "XXX_SYS_UNKNOWN", e);
    throw new BusinessException(BusinessErrorEnum.SYS_UNKNOWN.getI18nErrordesc());
}
```

## 4. 占位符与参数匹配

模板 `{0}{1}` 必须传入对应数量参数，禁止将 `e.getMessage()` 填入占位符。

```java
// ❌ BAD
throw new BusinessException(BusinessErrorEnum.XXX.getI18nErrordesc(e.getMessage()));

// ✅ GOOD
throw new BusinessException(BusinessErrorEnum.MDS_MATERIAL_NOT_EXIST.getI18nErrordesc(materialCode));
```

## 5. 报错文案规范与模板

### 5.1 规范与指导

- **业务导向**：报错文案必须让业务侧能「看懂、知道下一步该做什么」，避免只给出技术字段名或内部实现信息。
- **信息要素**（能说明白就不再额外堆技术细节）：
  - **是什么问题**：参数缺失、格式不合法、配置缺失、数据不存在/已存在、状态不允许、系统异常等；
  - **作用对象**：清晰点出「哪个业务对象/参数/配置项」；
  - **下一步动作**：提示「请检查…」「请前往…维护」「请稍后重试」等可执行建议。
- **报错语句必须包含错误码**：返回前端的报错文案中**必须显式包含错误码**（如 MDS001、SOP002），便于用户反馈、日志排查与问题定位。推荐格式：`[错误码] 业务文案`，如「[MDS001] 物料不存在，请确认后重试。」；或由框架在返回时统一拼接错误码与文案。
- **统一文案结构**：
  - 业务类文案推荐结构：**「对象/参数」 + 问题 + 下一步指引**，如「尚未配置『需求版本』，请前往『需求版本设置』完成配置后重试」；
  - 技术类异常一律收敛为业务理解层面的提示，如「系统繁忙，请稍后重试。如有问题请联系管理员，并提供错误码与追踪ID」。
- **禁止行为**：

| 禁止 | 说明 |
|------|------|
| `e.getMessage()`、`e.toString()` 透传 | 技术信息仅写日志，不返回前端 |
| 报错语句不包含错误码 | 返回前端的报错文案中必须显式包含错误码 |
| 「操作失败:」+ 异常信息 | 使用场景化固定文案 |
| 空泛「运行失败」「操作失败」无下一步 | 必须给出「稍后重试/联系管理员」等指引 |
| 参数缺失只说「不能为空」不指名称 | 使用「「{参数名}」不能为空」 |
| 配置缺失只说「未配置」不指路径 | 补充配置项名称或菜单路径 |
| 状态不允许只说「不允许」 | 补充当前状态与替代路径 |
| 暴露内部术语或实现细节 | 禁止透传 DTO/VO 类名、Service 名称、SQL 原文等 |
- **术语与文风统一**：
  - 统一使用「物料」（禁用：产品、商品）；「任务」（禁用：作业、Job）；「参数」（禁用：字段、变量）；
  - 句尾统一中文标点（。或！），避免「半角+全角」混用；
  - 参数名、配置项名用「」包裹，便于界面与文案对应，例如：「需求版本」「计划期间」「算法方案」。

### 5.2 推荐模板示例

以下模板均需在最终报错语句中**包含错误码**，格式示例：`[错误码] 业务文案`。properties 中可写为 `错误码 = [错误码] 业务文案`，或由框架统一拼接。

| 场景 | 推荐模板 |
|------|----------|
| 参数缺失 | [错误码] 「{参数名}」不能为空。 |
| 参数格式/范围 | [错误码] 「{参数名}」格式不正确或超出有效范围，请检查后重试。 |
| 配置缺失 | [错误码] 尚未配置「{配置项}」，请前往「{菜单路径}」完成配置后重试。 |
| 数据不存在 | [错误码] {业务对象}不存在，请确认后重试。 |
| 数据已存在 | [错误码] 「{对象标识}」已存在，请勿重复添加。 |
| 状态不允许 | [错误码] {业务对象}已{状态}，无法{操作}。 |
| 删除限制 | [错误码] {业务对象}存在关联数据，无法删除，请先解除关联。 |
| 并发冲突 | [错误码] {业务对象}已被他人修改，请刷新后重试。 |
| 权限不足 | [错误码] 无权限执行该操作，请联系管理员。 |
| 账号状态 | [错误码] 账号已{停用/锁定}，请联系管理员。 |
| 密码相关 | [错误码] 密码{过期/不符合要求}，请先修改密码。 |
| 导入/导出失败 | [错误码] {操作}失败，请下载错误明细并按提示修正后重试。 |
| 模板/格式不支持 | [错误码] 当前{模板/文件格式}不支持在本模块使用，请使用正确模板后重试。 |
| 任务运行中 | [错误码] 计划/任务正在运行中，请稍后再试。 |
| 计算/排程失败 | [错误码] {计划/排程}计算失败，请检查配置与数据后重试。 |
| 流程异常 | [错误码] 流程{启动/执行}失败，请稍后重试或联系管理员。 |
| 外部服务失败 | [错误码] 调用{服务名}失败，请稍后重试。 |
| 请求超时 | [错误码] 请求超时，请稍后重试。 |
| 系统错误 | [错误码] 系统繁忙，请稍后重试。如有问题请联系管理员，并提供错误码与追踪ID。 |

### 5.3 表格外场景的文案编写指导

对于表格中未列出的报错场景，开发与 AI 编码时须遵循以下指导原则：

#### 5.3.1 识别报错场景类型

1. **业务规则类**：业务逻辑校验失败（如库存不足、时间冲突、数量超限）
2. **数据依赖类**：依赖的主数据或关联数据缺失/异常（如工厂未配置、BOM 缺失）
3. **流程状态类**：当前状态不允许执行某操作（如已审批、已关闭、已锁定）
4. **计算引擎类**：算法执行、计划计算、排程引擎运行失败
5. **集成交互类**：调用外部系统、第三方服务、消息队列失败
6. **系统资源类**：内存不足、线程池满、数据库连接超时

#### 5.3.2 构造报错文案的三要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **对象** | 明确指出「哪个业务对象/参数/配置项」出了问题 | 「计划版本」「工单」「物料清单」 |
| **问题** | 用业务语言描述问题本质（缺失/格式错误/状态不允许/计算失败） | 「未配置」「格式不正确」「已锁定」「计算超时」 |
| **下一步** | 给出可执行的操作建议 | 「请前往…配置」「请检查…后重试」「请联系管理员」 |

#### 5.3.3 选择错误码前缀

根据报错发生的业务模块选择前缀：

| 模块 | 前缀 | 示例错误码 |
|------|------|-----------|
| 需求计划 | DFP | DFP001、DFP002 |
| 产销协同 | SOP | SOP001、SOP002 |
| 主生产计划 | MPS | MPS001、MPS002 |
| 物料需求计划 | MRP | MRP001、MRP002 |
| 主需求计划 | MDS | MDS001、MDS002 |
| 生产排程 | SCH | SCH001、SCH002 |
| 系统通用 | SYS | SYS001、SYS002 |

**注意**：新增错误码时，须先查找该模块是否已有可复用的错误码（场景相同或相近），优先复用可避免错误码膨胀。若确需新增，则查询 `BusinessErrorEnum` 枚举和 properties 文件，找到该模块已有错误码的最大序号，新错误码序号为最大序号 + 1，确保编码唯一性。

#### 5.3.4 处理复杂场景

| 场景类型 | 处理方式 | 示例 |
|----------|----------|------|
| **多个错误** | 优先报第一个阻断性错误，或汇总为「存在 N 处错误，请下载明细」 | 「导入数据存在 5 处错误，请下载错误明细并按提示修正后重试」 |
| **嵌套错误** | 只报最外层业务含义，技术细节写日志 | 「调用排程引擎失败，请稍后重试」（不透传「NullPointerException」） |
| **条件分支** | 根据不同条件返回不同文案，避免「操作失败」等空泛提示 | 库存不足 → 「物料库存不足，无法下达工单」；BOM 缺失 → 「物料清单不存在，请先维护 BOM」 |
| **批量操作** | 说明成功/失败数量，提供明细下载 | 「批量导入完成，成功 80 条，失败 20 条，请下载失败明细」 |

#### 5.3.5 表格外场景示例

**示例 1：库存不足（业务规则类）**

```
错误码：MRP015
中文文案：[MRP015] 物料「{0}」库存不足，当前可用库存 {1}，需求数量 {2}，请调整计划数量或补充库存后重试。
英文文案：[MRP015] Insufficient inventory for material "{0}". Available: {1}, Required: {2}. Please adjust plan quantity or replenish stock.
```

**示例 2：BOM 缺失（数据依赖类）**

```
错误码：MPS008
中文文案：[MPS008] 物料「{0}」未维护物料清单（BOM），无法生成生产计划，请前往「主数据管理 > 物料清单」完成配置后重试。
英文文案：[MPS008] BOM not configured for material "{0}". Cannot generate production plan. Please configure BOM in "Master Data > BOM" first.
```

**示例 3：计算引擎超时（计算引擎类）**

```
错误码：SCH020
中文文案：[SCH020] 排程计算超时（超过 300 秒），可能因数据量过大或约束条件复杂，请缩小计划范围或优化约束配置后重试。
英文文案：[SCH020] Scheduling calculation timeout (exceeded 300s). This may be caused by large data volume or complex constraints. Please reduce planning scope or optimize constraint settings.
```

**编写要点总结**：
- 报错语句必须包含错误码（格式：`[错误码] 文案内容`）
- 占位符 `{0}`、`{1}` 用于动态参数，须与代码中传入参数数量一致
- 中英文文案均需维护在 `messages_zh_CN.properties` 和 `messages_en_US.properties`
- 避免技术术语，使用业务侧能理解的语言
- 必须给出下一步操作建议，不得只说「失败」而无指引
